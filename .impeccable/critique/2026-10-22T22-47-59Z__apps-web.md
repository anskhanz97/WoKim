## Design-specificity verdict

WoKim has the start of a real identity: IBM Plex, paper/sheet surfaces, restrained cobalt and amber, preserved-source language, and the current-thread metaphor. Today feels authored; many project, task, people, and settings screens fall back to generic CRUD forms. The strongest product idea—saving the exact point where interrupted work should resume—is also the weakest workflow.

The deterministic scan produced six warnings. All were verified as false positives involving Angular-bound images or semantic error/notice borders. The important defects came from browser, DOM, keyboard, layout, and source inspection.

## Overall impression

The application is functional, calm, and trustworthy, but too administrative. Its biggest opportunity is to stop behaving like a collection of CRUD screens and become a purpose-built resume-my-work instrument.

## What is working

- The language is clear and product-specific.
- Source preservation, drafts, recoverable trash, local processing, and retention language create trust.
- Responsive layout, lazy routes, clean console output, and core text contrast are sound.

## Priority issues

### [P1] Interruption recovery does not fulfill the product promise

Replace Pause, Wait, and Switch with one compact Save resume point sheet. Prefill the next action, ask for one short checkpoint, allow Pause without note, and confirm where the user will resume. Surface it on Today, Task detail, Project Overview, and history.

### [P1] Quick Capture contradicts organize later

The current sheet exposes roughly 14 controls. Show only the note, type/attach/record methods, and Save initially. Move classification and transcription options under Organize now.

### [P1] Capture modal and forms need accessibility hardening

Focus escapes behind the dialog, the background is not inert, focus contrast is about 1.35:1, and required/error relationships are inconsistent. Use a native dialog or CDK focus trap, a 3:1 focus token, semantic form states, skip navigation, and current-page semantics.

### [P1] Mobile information architecture is incomplete

Search, People, Processing, Data & recovery, and Sign out disappear. Add persistent Search plus a clear More/Settings hub.

### [P2] Project workspaces lack location and visual cohesion

Build one shared project navigation component with active state, aria-current, 44px targets, and deliberate overflow/More behavior. Recompose Overview around Resume point, Current tasks, and Waiting.

## Visual-system direction

Keep the engineering-ledger concept. Preserve IBM Plex and paper/ink/cobalt/amber. Expand semantic tokens, carry the cobalt-to-amber thread across the product, use one labeled outline-icon family, prefer list/table hybrids over excessive cards, and standardize dialogs, sheets, comboboxes, badges, filter chips, action menus, and empty states. Keep native date controls while simplifying range selection. Establish semantic tokens before considering dark mode.

## Proposed sequence

1. Foundation and accessibility.
2. Signature interruption/resume workflow.
3. Fast capture and voice states.
4. Navigation and project information architecture.
5. Core work surfaces.
6. Profile, processing, recovery, sessions, and check-ins.
7. Efficiency layer: command palette, shortcuts, saved filters, bulk actions.
8. Bounded desktop/mobile, keyboard, screen-reader, motion, and regression verification.

## Questions to consider

- Should every Pause or Switch deliberately produce a resume point?
- What if Quick Capture exposed only the decision “what should I remember?”
- Is Today primarily a resumption dashboard or a daily journal?
- Should Project Overview follow resume, act, record rather than eight peer sections?
- Should the unmistakable WoKim moment be the thread changing from cobalt to amber when work is interrupted?
